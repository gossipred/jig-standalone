# 專題報告可能提問與準備回答

## Q1. 為什麼選這個專題？

**回答：**  
因為治具與模具管理是工廠現場很實際的需求。過去常用 Excel 或紙本，但當資料量增加後，很難追蹤狀態、附件與異動紀錄。我希望把自己的工程管理經驗結合 Java 程式設計，做出可以實際應用的系統。

## Q2. 這個專題跟一般 CRUD 有什麼不同？

**回答：**  
一般 CRUD 主要是新增、查詢、修改、刪除。本系統除了 CRUD，還加入角色權限、檔案上傳、Status old/new 異動紀錄、帳號密碼管理、半自動編號與 CSV 匯出，比較接近實務系統。

## Q3. 為什麼使用 Spring Boot？

**回答：**  
Spring Boot 適合快速建立 Java Web 系統，內建很多常用功能，例如 Web MVC、JPA、Security、測試整合。它可以讓我專注在系統功能，而不是花太多時間處理底層設定。

## Q4. 什麼是 MVC？

**回答：**  
MVC 是 Model、View、Controller。  
在本專題中，Model 是 Entity 與資料庫資料，View 是 Thymeleaf 網頁，Controller 負責接收使用者請求並回傳畫面。這樣可以讓程式分工比較清楚。

## Q5. 為什麼需要 Service 層？

**回答：**  
Controller 主要處理網頁請求，Repository 處理資料庫。如果把商業邏輯都寫在 Controller，程式會變得很亂。Service 層負責處理像權限、Jig No. 給號、異動紀錄、檔案限制等規則，讓程式比較好維護。

## Q6. 為什麼要做角色權限？

**回答：**  
現場不同角色的工作不同。OPERATOR 主要查詢，不應該能修改或刪除。ENGINEER 可以維護自己建立的資料。SUPERVISOR 可以管理團隊資料。ADMIN 管理帳號與最高權限。這樣可以降低誤操作風險。

## Q7. 為什麼 ENGINEER 只能改自己的資料？

**回答：**  
因為資料建立者通常最了解該治具或模具的狀況。如果每個工程師都能任意修改別人的資料，責任會不清楚。若需要跨人修改，則交給 SUPERVISOR 或 ADMIN。

## Q8. 你如何記錄資料異動？

**回答：**  
系統使用 `jig_logs` 資料表記錄異動，包括 action type、user、old status、new status、old due date、new due date、note 與時間。這樣可以追蹤誰在什麼時間改了什麼。

## Q9. 為什麼要記錄 Old / New？

**回答：**  
只知道有修改是不夠的。例如狀態被改過，但不知道從什麼改成什麼，追蹤價值就不高。記錄 Old / New 可以清楚呈現變更前後，對維修與管理很重要。

## Q10. 你如何處理密碼？

**回答：**  
密碼使用 BCrypt 加密後儲存，不直接保存明文密碼。ADMIN 可以建立帳號與重設密碼，使用者可以自行修改個人密碼，但不能修改帳號名稱，避免異動紀錄追蹤中斷。

## Q11. 為什麼帳號名稱不能修改？

**回答：**  
帳號名稱會出現在建立者、修改者與異動紀錄中。如果帳號可以任意改名，未來追蹤責任會變得混亂。因此帳號建立後固定，只允許改密碼。

## Q12. 為什麼用 MySQL？

**回答：**  
MySQL 是常見的關聯式資料庫，適合保存結構化資料，例如帳號、治具主資料、附件資訊與異動紀錄。也方便未來備份、還原與內網部署。

## Q13. 你如何測試這個系統？

**回答：**  
我使用 Spring Boot Test 與 H2 測試資料庫執行自動化測試。目前 `mvn test` 有 47 個測試通過，包含權限、搜尋、檔案、帳號、異動紀錄等功能。

## Q14. H2 和 MySQL 有什麼差異？

**回答：**  
H2 是記憶體資料庫，適合自動化測試，因為測試時不需要真的啟動 MySQL。正式執行時使用 MySQL。這樣開發測試比較快，也比較不受環境限制。

## Q15. 這套系統未來如何部署給客戶？

**回答：**  
最簡單是指定一台電腦當 server，安裝 Java、MySQL 與系統 JAR。其他使用者在同一個內部網路，用瀏覽器連到 server IP，例如 `http://192.168.1.50:8080`。未來可再加一鍵啟動與備份還原腳本。

## Q16. 目前還有哪些可以改善？

**回答：**  
可以補強刪除稽核紀錄、備份還原、一鍵安裝、Excel 匯入、QR Code 掃描查詢、Dashboard 統計，以及更完整的客戶操作手冊。

## Q17. 如果老師問：這份專題中你學到最多的是什麼？

**回答：**  
我學到 Java Web 系統不是只有寫語法，而是要思考資料庫、權限、流程、測試與使用者需求。尤其是需求會因測試而改變，程式也要能跟著調整。

## Q18. 如果老師問：你覺得最難的是什麼？

**回答：**  
最難的是權限與異動紀錄，因為不同角色能做的事不同，而且修改資料後要正確記錄誰改、何時改、舊值與新值。這比單純新增查詢複雜很多。

## Q19. 如果老師問：你如何避免資料重複？

**回答：**  
Jig No. 儲存前會檢查不可重號，資料庫也有 unique key。前端提供半自動給號，但最後仍由後端與資料庫確認，避免只靠畫面檢查。

## Q20. 如果老師問：AI 在這個專題中的角色是什麼？

**回答：**  
AI 協助我整理需求、檢查程式、產生測試與文件，但系統需求來自我的工程管理經驗，我也持續測試畫面並提出修正。AI 比較像助教與 pair programmer，不是取代我理解專題。
