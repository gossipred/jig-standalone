# PLAN-jig.md 審查紀錄

審查日期：2026-05-21

## 總評

這份計劃方向完整，適合作為第一版 Spring Boot + MySQL 專案的藍圖。它已經涵蓋資料庫、登入權限、治具資料管理、異動紀錄、CSV 匯出與未來 Notion 匯入預留欄位。

用比較生活化的方式說：這份計劃不像只寫「我要蓋房子」，它已經有房間配置、水電方向和第一批家具清單，可以開始施工。

## 做得好的地方

- Phase 拆分清楚，從資料庫開始，再到後端、登入、治具管理與匯出。
- 角色權限明確，`ADMIN`、`ENGINEER`、`OPERATOR` 的責任有區分。
- Jig No. 規則有先定義，這對治具管理很重要，否則日後資料會變成同一支治具有三種名字。
- Due Date 修改有保存歷史，符合管理追蹤需求。
- Notion 匯入先預留欄位，但第一版不硬做，範圍控制合理。

## 建議修正或補強

1. 增加資料表欄位型別

   原計劃列出欄位名稱，但尚未明確定義 MySQL 型別、長度、是否允許空值。已先在 `data/schema.sql` 補上第一版草稿。

2. 明確定義 `jig_logs.action_type`

   建議第一版使用固定值：

   - `CREATE`
   - `UPDATE`
   - `STATUS_CHANGE`
   - `DUE_DATE_CHANGE`
   - `NOTE`

3. 狀態值建議先固定

   建議資料庫與程式都限制為：

   - `Normal`
   - `Repair`
   - `Scrap`
   - `Hold`

4. 預設帳號密碼不應長期使用 `123456`

   第一版展示可以用，但正式環境要改成強密碼，並且只保存 BCrypt 加密後的密碼。

5. Jig Picture 第一版改為上傳檔案

   使用情境確認後，第一版改成可上傳治具圖片或圖紙檔案，檔案預設存放在 `uploads/jigs/`。每個 Jig 初步限制最多 5 個檔案，並提供下載功能。上傳檔案使用 `jig_files` 表保存，資料庫欄位 `jig_picture_url` 暫時保留作為相容欄位。

6. 建議補一份操作流程圖或頁面清單

   第一版可以先定義頁面：

   - 登入頁
   - 治具列表頁
   - 治具新增頁
   - 治具修改頁
   - 治具明細與紀錄頁

## 第一版範圍建議

第一版建議目標是「可展示、可查詢、可管理、可追蹤」。

必做：

- 登入與登出
- 角色權限
- 治具列表與搜尋
- 新增與修改治具
- 狀態更新
- Due Date 更新與歷史紀錄
- CSV 匯出

先不做：

- Dashboard 圖表
- 圖片上傳
- 使用者管理畫面
- Notion 自動同步
- 列印格式
